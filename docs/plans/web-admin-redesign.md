**三个核心流程**

1. **查用户 → 续费 → 确认结果。** 账号可点击打开详情；会员、设备、兑换记录同处一个上下文。默认“续费叠加”：起点取当前有效到期时间与当前时间的较晚者；提供套餐和自定义天数，中文选择，不再要求输入 month/custom。提交前显示当前到期日、新到期日和增加时长。永久会员默认不允许意外改为有限期；“调整到期日”“撤销会员”是独立的高级操作。封禁与会员状态分开显示，给封禁账号续费不会自动解封。
2. **生成一批码 → 检查 → 复制或导出。** 点击“生成兑换码”打开有明确标题的侧栏/表单；填写套餐、数量、兑换截止时间、批次备注。区分“兑换码何时不能再兑换”和“兑换后获得多少会员时长”。生成后进入持久的批次结果页，支持复制全部、导出本批次和返回列表；刷新后仍能找回，提交重试不会生成第二批。
3. **用户反馈不能用 → 查原因 → 处理 → 留痕。** 详情清楚区分会员到期、封禁、会话失效、设备换绑冷却。展示实际存在的数据，“最近登录”“最近校验”不能拿 updated_at 冒充。解绑设备、解除冷却、重置密码分别解释影响；执行后只刷新相关数据并留在当前用户。

补充会员操作契约：保持现有固定套餐天数语义（月 31、季 93、半年 186、年 366），本轮不静默改成自然月。将来若调整计费口径，需独立版本与迁移规则。单条和批量续费使用同一业务逻辑；永久会员在有限期续费时跳过并说明，不能降级。会员变更需要 operation_id 防止重复提交；提交时检测版本冲突，旧预览不能覆盖期间发生的兑换。

这些选择遵循 rule/name-object-scope-consequence、rule/irreversible-action-safeguard、rule/no-redundant-entry、rule/one-primary-action。

**分页、筛选与批量操作的明确规则**

- 所有列表共用分页控件：默认 25 条，可选 25/50/100；页码、上一页/下一页、跳页、总条数和当前区间。固定表头与底部工具条不得遮挡末行。
- 搜索、状态、排序、page、page_size 存入 URL；刷新、复制地址、前进/后退均恢复。改变筛选或排序回到第 1 页；刷新当前页不清空筛选。
- 用户支持账号/ID/设备搜索；常用状态区分未开通、有效、即将到期、已到期、已封禁；高级筛选提供套餐、注册日期、到期日期、设备状态。分类由服务端业务状态定义，不能只按文字拼接。
- 排序由服务端完成，白名单字段；日期排序追加唯一 ID/兑换码作为稳定的第二排序键。删除最后一条导致页码越界时，返回并跳到最后有效页。
- 勾选在同一查询的跨页切换中保留；筛选或排序变化时清空并提示。显示“已选 N 条，其中 M 条在其他页”，可以查看/移除选中项。
- 第一版只支持明确的 ID 集合：用户最多 100 个、兑换码最多 500 个，匹配现有操作上限。默认“全选本页”；不把一个复选框悄悄解释成全库全选。批次级操作单独展示批次和实际受影响数量。
- 导出入口明确为“导出当前筛选”和“导出已选”。服务端与列表复用搜索条件；不会丢掉 q、日期、套餐等条件。无筛选导出全量时展示预计范围；大量数据以分块/流式生成，避免全部装入内存。
- 批量执行前展示动作、数量和影响；结果区分成功、状态不适用、冲突、失败，失败项可再次查看。整体事务失败不得伪装成部分成功。
- 搜索去抖并取消旧请求/拒收过时响应；旧搜索不能覆盖新结果。列表失败提供局部重试，保留筛选和上次成功内容，并标记数据可能过时。
- 先使用服务端页码分页满足直接跳页，不为预计中的大数据量提前改成不支持跳页的游标方式；真实慢查询出现后再评估。

遵循 rule/preserve-mental-model、rule/name-object-scope-consequence、rule/cover-reachable-states、rule/error-states-recovery。

用户反馈首版“清爽工作台”过于简单。当前视觉候选已升级为“蓝调创作工作室”：深海军蓝导航、分层的浅色工作区、品牌蓝主操作，结合会员概况、清楚的用户行、批量操作和详情区，提升完整度。官网用更完整的产品展示区建立识别度。浅色默认仍是设计建议，未当作用户已经选定的偏好；深色共用同一组语义 token，不再使用纯黑底和发光渐变。对话方向稿随宿主的明暗外观展示。

| --- | --- | --- |
| 蓝调创作工作室（新推荐） | 海军蓝侧栏 + 分层数据区；会员概况可点选筛选；用户头像、账号与权益分层展示；支持跨页选择与批量续费预览；官网采用非对称标题/下载区与深色产品展示面板 | 与用户/会员/兑换码的查找、筛选、批量运营最匹配，作为 S1 视觉候选 |

设计应优先通过字号、留白和对齐建立层级。桌面正式页面用 14px 正文与表格文字，不用缩字号换密度；密度切换只改变行高与间距。危险操作收进“更多”，主列表不同时展开全部账号按钮。控件使用统一圆角、边框、图标尺寸和焦点样式，避免每块功能各做一套。

官网与后台分别设计。官网首屏用一句具体功能说明、真实客户端截图/录屏和清晰下载入口；修正当前大标题尴尬断行。布局顺序：产品说明与下载 → 真实功能演示 → 三步使用 → 套餐及开通方式 → 安装/便携下载、版本说明和完整 SHA-256 复制 → 帮助/联系。没有支付时使用真实的联系开通途径，不出现无法执行的“立即购买”。联系渠道未配置时隐藏对应按钮，不造二维码、不用“后台配置”面向访客。

官网视觉主张是“专业的视频生产工具”：产品名、清晰的一句话用途、下载入口与产品画面形成首屏。新版品牌标题为“让创意，成批发生。”，辅以视频片段、音乐、字幕与组合导出的具体用途；中文使用 Noto Sans SC 的层级，提供本地中文字体回退。新增展示区包含素材列表、组合预览、画幅与输出设置、片段组合顺序；三步工作流可切换查看说明。安装版/便携版使用独立选择面板。

避免通屏卡片、彩色胶囊标签、假业绩数字和巨大空口号。新版展示区明确标为“工作流概念预览 · 非当前客户端截图”，只是官网视觉候选，不能据此默认重做桌面客户端；正式官网应换成真实客户端录屏/截图，不把概念 UI 当作已有功能或性能证明。动画仅用于必要的状态反馈，尊重减少动态效果设置。

新版方向稿已演示跨页选择 2 位用户、批量续费预览及确认、筛选变更清空选择、兑换码搜索与导出范围提示。界面中的人数由同一组合成记录计算；不加入没有来源的收入、在线人数、增长率或运行性能指标来增加视觉复杂度。

遵循 rule/structure-before-containers、rule/accessible-name-required、rule/keyboard-complete-flow；具体颜色和字号是 ui-design Direction 的建议，不是已经测量通过的新界面。

**所有页面需要覆盖的状态**

| 场景 | 预期表现 |
| --- | --- |
| 首次加载 | 保留布局的骨架；只阻塞当前区域 |
| 无记录 / 搜索无结果 | 前者给首次操作入口，后者给清除筛选；不把二者混为“暂无数据” |
| 详情接口失败 | 在详情侧栏展示重试和关闭，不只在侧栏外显示错误 |
| 提交中 / 超时 | 控件稳定、禁止重复提交；超时保留输入，用 operation_id 查询或重试，避免重复续费、重复发码 |
| 登录过期 | 保留无敏感内容的草稿与返回地址，重新登录后恢复；密码、Token 不存草稿 |
| 并发变更 | 返回冲突，展示最新状态并重新确认；不能静默覆盖 |
| 部分操作不适用 | 例如已兑换码不能停用、永久会员无需有限期续费，列明原因 |
| 删除/撤销/封禁 | 显示对象和后果，危险动作进入“更多”；不可逆操作用明确命名确认 |
| 恢复 | 只有能完整恢复关系时提供“撤销”。解封不代表恢复旧会话，撤销会员不能给虚假的一键恢复承诺 |
| 未保存修改 | 刷新列表不覆盖其他表单；离开有草稿的编辑页时提示，失败后不清空字段 |

遵循 rule/cover-reachable-states、rule/preserve-user-input、rule/undo-only-when-honest、rule/destructive-proportional。

**实现路线和文件边界**

推荐新建独立 `web-admin/`，使用 React + TypeScript + Vite，复用项目现有的前端工具知识；后台表格、分页、表单、抽屉采用一套 Ant Design 组件并统一 token。新增组件库的理由是跨页选择、服务端排序、日期表单、键盘操作和弹层状态已有具体需求，避免继续扩展一份全局 DOM 脚本。先不引入完整后台脚手架、图表平台或新的状态管理框架。具体依赖版本在实施时核对兼容性并锁定。

Ant Design 已提供表格选择、排序、固定列和分页配置，以及跳页和页大小控件；仍需自行实现本计划的服务端契约和操作语义。[Table 文档](https://ant.design/components/table/) · [Pagination 文档](https://ant.design/components/pagination/)。Vite 支持将静态产物集成到现有后端。[后端集成文档](https://vite.dev/guide/backend-integration.html)。

| 边界 | 计划 |
| --- | --- |
| 前端 | web-admin/src 下按 pages/users、codes、releases 等组织；共用 AppShell、ServerTable、QueryFilters、MutationResult、UserDetail |
| API | 保留 /api/auth/*、/api/redeem、/api/update/* 的客户端合同；后台新增明确的 membership/operations 接口，旧接口保留并修正语义 |
| 查询合同 | 列表与导出复用筛选；返回 items、total、page、page_size、pages；增加排序白名单、状态定义和时间区间 |
| 数据 | 只做增量迁移；增加必要的用户备注、可检索批次信息、操作去重记录和结构化变更记录；既有日志继续可读，不伪造历史 |
| 路由 | /admin/* SPA 路由与 /admin/api/*、登录/退出端点明确分开；直接访问子页和刷新要正常；未登录不能取得受保护数据 |
| 会话 | 保留 HttpOnly Cookie 与写操作 CSRF；只保留一个服务端 worker，直到共享会话方案另行验证 |
| Docker | 前端在镜像构建阶段产出静态文件，由 FastAPI 提供；运行期继续是一个 Python 服务、一个数据卷 |
| 官网 | 本轮沿用 server/templates/site.html 与 static/site.*，优化内容和下载/开通流程，不强制搬进后台框架 |
| 文件整理 | 仅当某个页面的业务重写需要时抽取对应服务模块，避免先拆完整后端再交付可用页面 |

**分阶段交付，每一步都能实际使用**

| 阶段 | 可交付结果 | 依赖和完成标准 |
| --- | --- | --- |
| S0：修正高影响行为 | 旧后台先修续费叠加、搜索导出范围；修复 WAL 备份、服务端 Token 摘要兼容绕过及换绑竞态 | 样例剩余 42 天续 31 天后约剩 73 天；筛选 1 条导出 1 条；WAL 备份恢复不丢提交；摘要不能直接作为凭据；并发换绑仅一个成功。原生客户端门禁修复是独立客户端工作，不伪装成 Web 已解决 |

**验收场景**

- 用 137 个合成用户验证 25 条/页共 6 页，跳最后页、切 50/100、删除末页唯一记录；URL、返回和刷新一致。
- 跨页选择后执行批量操作，只影响明确 ID；改变筛选后及时清空并提示；超过上限无法提交。
- 剩余 42 天、已到期、永久、封禁四种会员均测试单条/批量续费；重复 operation_id 不重复增加时长；期间发生兑换时报告版本冲突。
- 搜索唯一兑换码后导出 1 条；“导出已选”仅包含所选 ID；使用/停用/过期组合按业务状态一致展示。
- 发码提交期间断网/超时，恢复后根据 operation_id 找回原批次；不重复生成；已使用码不可重新变为可兑换。
- 有冷却用户时持续键盘导航，按钮焦点不被每秒更新抢走；详情可用键盘打开、关闭并回到原位置。
- 用户列表请求 500、详情请求 500、401 过期、空列表、慢请求逆序返回分别有对应恢复表现；不删除表单草稿。
- 1440/1280/390px、200% 缩放、长中文账号/备注、长设备 ID、0/1 条记录均检查；末行不被分页遮挡。
- 现有命令 `python -m unittest discover -s tests -v` 必须继续通过；新增 API 回归和上述关键浏览器流程。新增 Web 应提供 build/typecheck/test:e2e 命令，具体脚本随实施创建。
- 以 1 万用户、10 万兑换码的合成库检查查询计划和列表 API 延迟，建立同机基线；不把本机数字承诺为线上 SLA。列表请求仅加载当前业务页，不打开后台即同时请求所有业务。

**迁移与恢复**

先修备份，再对生产副本 dry-run；确认用户、会话、已使用兑换码和发布信息数量。新字段与表仅增不删，旧数据可读。按页面切换新旧入口；旧入口同样具备登录与 CSRF，保留 S0 修正，不能回退到会缩短续费时长的原版。只更换 Web 后台时递增 SERVER_VERSION，不触碰客户端固定身份和 APP_VERSION。

出现 UI 问题先回退前端入口/镜像，保留兼容的新表；生产已产生新数据后，不直接覆盖旧数据库备份。数据错误通过带审计的修正操作处理；必须整库恢复时需单独确定新增数据的处理方案。
