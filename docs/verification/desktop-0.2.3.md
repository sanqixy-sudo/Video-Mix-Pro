# 桌面客户端 0.2.3：授权与执行修复

本次在 0.2.2 便携运行适配基础上改动桌面业务执行代码。沿用桌面 UI 和现有账号协议；不改生产用户、套餐、兑换码或 Web 部署。

## 已实施

| 问题 | 改动与实际行为 |
| --- | --- |
| 只有 React 检查会员，直接 IPC 能启动任务 | 混剪、套外框、水印、去重、重试统一先由 Rust 向官方 HTTPS 服务验证；不信任本地 active、plan、到期日。队列调度时再次验证当前会话，退出或换账号后旧队列不能继续开始处理 |
| 可把服务器地址改成伪造响应服务 | 正式程序只信任现有官方地址，禁止重定向，保持 TLS 证书验证；不会把 Token 发给其他地址。需要自建授权域名时应单独配置并构建信任范围 |
| 同步硬件检测、目录扫描与任务准备阻塞原生命令 | 移入工作线程；硬件检测在进程内复用，命令探测最长 10 秒；授权连接最长 8 秒 |
| 取消依赖 FFmpeg 输出，混剪当前步骤不能停止 | 所有四类任务统一使用可取消的进程执行器，每 50ms 检查取消，回收子进程与输出读取线程 |
| FFmpeg 错误日志无限积累 | stdout 尾部最多 256 KiB、stderr 最多 64 KiB、进度通道最多 64 项；任务日志仍保留最近 500 条 |
| 失败/取消产生正式半成品，重试会跳过 | 输出先进入临时文件，成功且未取消才替换正式文件；已有文件在处理失败时保留 |
| 并发进度使用视频序号估算 | 汇总各个运行中任务的分量及实际完成数，避免后面的短视频先结束导致进度虚高或倒退 |
| 重复音频/时长探测及素材列表复制 | 每批次按路径、大小、修改时间复用一次 FFprobe JSON 探测；混剪工作线程借用素材列表 |
| 历史 UI 只剩 50 条，但归档配置一直增长 | 淘汰历史条目时同时释放对应归档和探测缓存 |
| 清空素材目录后被旧扫描响应覆盖 | 清空和 effect 清理都会作废请求编号 |
| 定时状态请求重叠、闲置任务页频繁重绘 | 请求结束后再安排轮询，IPC 请求复用；空闲 5 秒、运行 1 秒，相同结果不更新 React 状态 |
| 首屏加载所有页面 | 除默认混剪页外，其余七个页面按需加载；补齐任务操作失败提示，防止重复点击 |
| 素材目录中的同名 EXE 被优先执行 | 处理工具只从应用资源、程序目录或系统 PATH 查找 |

每次新提交和队列开始都需要联网验证；已运行的当前批次允许完成，下一批次再检查。无离线授权机制。正式程序不提供本地测试服务器或跳过门禁的开关，隔离测试只在 Rust 单元测试中使用本地 HTTP 响应。

原生网络库启用 Windows 系统代理支持，与用户现有网络设置一致。实际验收发现未启用该特性时此机器的直连请求超时，修复后官方 HTTPS 健康接口只读检查通过；没有关闭证书验证或改用 HTTP。

## 验证

- 前端 TypeScript / Vite 构建通过。
- Rust release 回归 12 项通过：伪造本地 active、伪造服务器、过期与设备不匹配、HTTP 拒绝/重定向/异常响应/超时、安静子进程取消与超时、日志上限、并发进度、取消时输出保护、归档清理、实际媒体流程。
- 内置 FFmpeg 实际执行混剪（并发两条）、套外框、水印、去重，五个输出均有音频和有效时长；损坏素材没有覆盖已有输出。
- 真实 FFmpeg 取消测试在发出取消前等待 300ms，最终回归总时长 316ms；这是本机合成素材检查，不代表所有机器的延迟。
- 两条并发混剪重复同一片段只执行一次 FFprobe；素材改变大小或修改时间会用新键探测。
- 主入口 JS 从 296.49 KB 降至 249.91 KB（约 15.7%），gzip 从 89.34 KB 降至 77.98 KB（约 12.7%）；其余页面代码延后加载，并非删除功能。未宣称所有视频转码速度提高。

媒体证据见 [实际视频回归](desktop-0.2.3-media.json)，完整原生回归输出见 [测试日志](desktop-0.2.3-rust-tests.txt)。

最终交付验收完成：

- 安装包 7-Zip 完整性检查与解包通过，主程序、FFmpeg、FFprobe、两个 DLL 的 SHA-256 与构建源文件一致。
- 从最终便携 ZIP 完整解压并实际启动 0.2.3，验证内置 WebView2、独立账号目录、全部八个页面，页面脚本错误 0。
- 真实原生 IPC 验证四个提交入口和重试入口均拒绝未登录状态；伪造本地永久会员及服务器地址被拒绝；通过原生 HTTPS 请求官方服务时，无效 Token 正确被拒绝。
- 在独立 Edge 中模拟延迟响应，清空输入后的旧结果、扫描乱序、慢轮询与手动刷新去重均通过。正式程序保持只读 IPC 接口，没有为测试增加可用来绕过授权的开关。
- 最终两个文件及便携包 265 项清单哈希一致，干净交付目录不包含 data、账号会话或测试数据。

同机三次重复硬件检测调用（含 WebView IPC 测量开销）：0.2.2 为 1377.92/1195.83/1292.72ms；0.2.3 为 27.37/12.69/5.46ms。新版复用本进程已有检测结果；这不是冷启动时间或转码速度对比，构建期间的机器负载也会影响数值。

证据：[旧版基线](desktop-0.2.2-baseline.json)、[最终 ZIP 原生验收](desktop-0.2.3-native.json)、[慢请求浏览器回归](desktop-0.2.3-request-tests.json)、[安装器校验](desktop-0.2.3-installer.json)、[构建与文件哈希](desktop-0.2.3-build.json)。
